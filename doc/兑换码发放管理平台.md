# 兑换码发放管理平台（简版需求）

## 1. 目标

基于当前 React + Vite + Hono + Cloudflare Workers 项目开发，继续使用 Drizzle ORM + D1 存储数据。用户无需注册账号，通过不同的 Key 分别完成发码管理和领码。

## 2. 凭证说明

| 名称                 | 用途                                                                                                                              |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 发码 Key             | 系统生成的长随机字符串，是发码者重新登录管理页面的凭证，由用户自行保存                                                            |
| 登录态 Token         | 创建或登录发码空间时生成，用于后续管理请求的身份校验，有效期内无需重复输入发码 Key                                                |
| 领码 Key             | 对应一个兑换码池，可分享给领码者，用于进入领码页、领取一个未领取的兑换码及提交使用标记，不提供码池内兑换码列表的访问权限          |
| Turnstile 验证 Token | 人机验证通过后由 Cloudflare 签发，随领取请求提交并由服务端核验；与登录态 Token、领码 Key 不同，不作为领取者身份或本地领取记录保存 |
| 兑换码               | 发码者导入、领码者实际领取的内容，与上述凭证不同                                                                                  |

## 3. 页面与流程

### 首页

直接访问时展示两个入口：**我要发码**、**我要领码**。

### 我要发码

1. 点击“我要发码”后弹窗，提供两个选项：**生成新 Key**、**使用已有 Key**。
2. 选择“生成新 Key”：创建发码空间，生成并展示发码长 Key，支持复制，提示用户妥善保存且丢失后不提供找回；同时生成登录态 Token，用户确认已保存 Key 后进入管理页面。
3. 选择“使用已有 Key”：展示输入框，用户提交已有发码 Key；校验通过后生成登录态 Token，进入对应空间的管理页面，校验失败则提示错误并允许重新输入。

仅打开弹窗不创建发码空间或生成 Key。后续直接访问管理页面时，有效登录态可继续使用；登录态失效时，通过上述弹窗选择“使用已有 Key”重新登录。

登录态自创建起固定有效 7 天，访问期间不自动续期，关闭浏览器后在有效期内仍可继续使用。同一浏览器只保留一个当前空间的登录态；创建或登录另一空间成功后切换到该空间，登录失败则保留原登录态。其他设备的会话不受影响。

管理页面的最小功能：

- 创建兑换码池：只提交码池名称，名称去除首尾空白后不能为空，在同一发码空间内不能重名；创建成功后得到一个空池，默认处于发放中。
- 修改兑换码池名称：发放中和已停止的码池均可修改名称，沿用创建时的非空、同空间不重名规则。仅修改名称，保留原领码 Key、链接、库存、领取记录及使用标记；管理端和重新打开的领码页展示新名称，本地领取历史仍保留领取时保存的名称，不主动同步。
- 批量导入兑换码（每行一个）：新建码池和首次导入是分开的两个动作，允许码池一直为空；首次导入与后续追加使用相同规则，单次最多 500 条，单码最长 100 个 Unicode 码点。合法行正常导入，失败行跳过，并展示原始行号及失败原因；导入失败不删除已创建的码池。
- 向已有兑换码池追加兑换码，继续使用原有领码 Key 和链接；导入完成后展示成功数量、失败数量和失败行明细。
- 停止兑换码池发放：停止后不能再领取新码，但已有领取记录仍可查看和标记“我已使用”；追加兑换码不会自动恢复发放。
- 恢复兑换码池发放：允许手动将已停止的兑换码池恢复为发放中，继续使用原有领码 Key 和链接，按剩余库存发放，保留已有领取记录和使用标记。
- 为每个兑换码池生成领码 Key 和领码链接，支持复制分享。
- 查看各兑换码池的总数量、已领取数量、剩余数量，以及兑换码领取状态、领取备注、用户是否标记已使用和标记时间。
- 退出登录，清除当前登录态。

### 我要领码

1. 点击后弹窗要求输入领码 Key。
2. 校验通过后进入对应兑换码池的领码页；无效时提示错误，允许重新输入。
3. 通过带领码 Key 的链接（如 `/claim?key=xxx`）访问时，自动校验并直接进入领码页。
4. 校验通过后，读取当前浏览器的本地领取记录：若已有该领码 Key 的记录，直接展示已领取页面，不再提供领取按钮；否则展示兑换码池名称、剩余数量、“备注（选填）”输入框和“领取兑换码”按钮。备注允许留空，最多 500 字，提示“备注将提供给发码者查看”；不填写也可正常领取。可领取时加载 Turnstile Managed 验证组件，验证未通过、已过期或正在提交时禁用领取按钮。右上角展示“已领取的兑换码”按钮，点击后弹窗查看本地保存的领取记录。
5. 点击领取时再次检查本地是否已有该领码 Key 的记录；已有则展示原兑换码，不发起领取请求；没有且人机验证已通过时，将领码 Key、可选备注（`remark`）和 Turnstile 验证 Token（`turnstileToken`）一并提交到领取 API。服务端先校验领码 Key、码池状态和备注，再向 Cloudflare 核验验证 Token；全部通过后，从当前兑换码池选取一个未领取的兑换码，在同一原子操作中标记为已领取、记录领取时间并保存备注，成功后才将兑换码返回前端。备注校验失败时保留输入并提示修改，不分配兑换码。人机验证失败、过期或服务异常时不分配兑换码，保留备注并提示重新验证。重试领取前重新获取验证 Token，不自动重发领取请求。前端按本地记录合并规则将兑换码和兑换码池信息保存到 `localStorage`，进入已领取页面，展示本次领取结果并支持复制。库存耗尽时提示“兑换码已领完”；兑换码池停止发放时提示“该兑换码池已停止发放”并禁用领取按钮。
6. 已领取页面提供“我已使用”按钮，提示“此操作仅记录你的使用标记，实际使用情况由发码者自行验证”。点击后，前端将该兑换码作为参数调用 API，记录用户标记已使用及标记时间；成功后按钮变为“已标记使用”并禁用。

打开链接或进入页面只做校验和展示，点击领取按钮后才实际分配兑换码。

领取接口通过领码 Key 确定兑换码池，在服务端完成选码和标记已领取，每次成功请求只返回本次分配的一个兑换码，前端无需再单独调用标记已领取接口。领码端不提供码池内兑换码列表或他人已领取兑换码的查询接口；校验接口只返回领码页所需的码池名称、状态和剩余数量等信息，不返回兑换码内容。使用标记接口通过领码 Key 和兑换码内容定位记录，标记失败时保留当前兑换码，允许重试；首次标记和重复提交均返回成功及服务端保存的使用标记和首次标记时间，前端据此更新页面及对应本地记录。两者均不识别领取者身份，不生成专属领取凭证。

停止发放不影响领码 Key 校验和进入领码页，用户仍可打开右上角的“已领取的兑换码”弹窗。

### 已领取的兑换码弹窗

- 从 `localStorage` 读取当前浏览器保存的领取记录，每个 `claimKey` 最多对应一条领取记录，展示兑换码池名称、兑换码、领取时间和用户使用标记；没有记录时显示“暂无已领取的兑换码”。
- 每个兑换码支持复制和点击“我已使用”。标记时使用该记录所属兑换码池的领码 Key 和兑换码调用 API；成功后同步更新本地记录及页面展示，失败时提示错误并允许重试。
- 已标记的兑换码显示“已标记使用”，禁用重复操作；此处同样说明该标记仅为用户声明，实际使用情况由发码者自行验证。
- 本地记录不设置自动过期，刷新或重新打开浏览器后可继续查看；仅保存在当前浏览器，清除浏览器数据后无法从本地恢复，不做跨设备同步。
- 本地展示的是最后一次成功保存的状态，不主动向服务端同步，首版不增加单条领取记录的状态查询接口。若服务端已标记使用但响应丢失，本地可能仍显示未标记，用户再次提交后通过成功响应及首次标记时间修正本地状态。

## 4. 基本规则

- 发码 Key 与领码 Key 分离，领码 Key 不具备管理权限。
- 每个发码者只能管理自己空间内的兑换码池与兑换码。
- 发码 Key、领码 Key 和登录态 Token 由服务端安全随机生成；发码 Key 不放入 URL，登录态 Token 通过 HttpOnly Cookie 保存，服务端校验有效期。Turnstile 验证 Token 由 Cloudflare 签发，仅用于本次领取验证。
- 发码 Key 丢失后不提供找回；已有登录态有效期间仍可管理，登录态失效后无法重新进入原空间。
- 服务端选码与标记已领取必须原子完成，成功后才返回兑换码，确保并发领取不重复发放；首次导入和追加时均跳过同一码池内的重复兑换码，并返回失败行号及原因，不影响其他合法行导入。
- 码池名称去除首尾空白后不能为空，以处理后的名称判断同一空间内是否重名，区分大小写；不同空间允许同名。创建码池与导入分别提交，导入全部失败时仍保留空池。
- 导入按原始文本行号反馈结果：每行先去除首尾空白，忽略空行（不计入成功或失败数量），兑换码区分大小写；按 Unicode 码点计数，长度为 1–100。同批重复码仅首次合法出现的行可导入，后续重复行失败；与码池内已有兑换码重复的行也失败，无论已有兑换码是否已领取。失败原因须明确，如“超过 100 字”“与本批第 N 行重复”“码池中已存在该兑换码”。
- 单次导入按去除空行后的输入行数计算上限，重复或超长行仍占条数；超过 500 条时整次请求不执行导入，提示拆分后重试，不静默截取前 500 条。上限内逐行处理，合法行成功、失败行跳过；全部为空时提示“请输入兑换码”，不写入数据。前后端使用一致的输入校验规则，最终以服务端结果为准。
- 领取按钮提交期间禁用，避免连续点击重复请求。已领取的兑换码不自动回收或重新发放。
- 领取备注为选填纯文本，前后端均先去除首尾空白，再按 Unicode 码点计数校验最多 500 字；未传、`null` 或去除空白后为空时保存为 `NULL`。备注随领取保存，供所属空间的发码者查看，展示时按纯文本处理；首版不提供领取后修改备注的功能。
- 首版不处理服务端已标记领取、但响应丢失导致前端未收到兑换码的情况，不增加领取请求编号或找回机制；该码保持已领取状态。
- 领取状态与用户使用标记分别记录：领取成功不代表已使用，未点击“我已使用”也不代表实际未使用。使用标记不改变领取状态或剩余库存，重复提交仍返回成功和首次标记时间，不重复记录或覆盖首次标记时间。
- “用户标记已使用”仅为领码者自行声明，不代表兑换码已实际核销；真实使用情况由发码者自行验证，验证流程不在系统设计范围内。
- 首版不建立领码者账号、不校验兑换码归属。前端依据本地记录限制同一领码 Key 只能领取一次，标记已使用后也不能再次领取；服务端不识别领取者，不实施每人限领。清除或修改本地数据、更换浏览器或直接调用接口均可绕过本地限制，该限制不作为防刷措施。标记接口只校验领码 Key、兑换码是否属于该兑换码池及其状态，“我已使用”仅适用于已领取的兑换码。
- 本地领取记录以领码 Key（`claimKey`）为唯一键，每个 Key 最多保存一个兑换码，用于本地限领、展示和发起操作，实际领取状态与用户使用标记以服务端记录为准。若本地保存失败，当前页面仍展示已领取结果并禁止继续领取，提示用户复制保存兑换码；不影响服务端已完成的领取，但重新打开页面后无法依赖该记录限制再次领取。
- 本地记录写入须在同一浏览器内串行执行，每次写入前重新读取并合并已有数组，保留其他码池的记录，避免不同标签页用旧数组互相覆盖。同一 `claimKey` 已存在不同兑换码时保留已有记录，当前页面继续展示本次领取结果并禁止继续领取，提示“本地已保存该码池的另一个兑换码，本次兑换码未存入领取记录，请复制保存”。使用标记结果仅更新 `claimKey` 和 `code` 均匹配的本地记录，不能覆盖同一 Key 下的另一个兑换码。首版不保证跨标签页只领取一次，多个标签页仍可能分别成功领取不同的码。

### 4.1 领码防刷与 Turnstile

- 首版使用 Cloudflare Turnstile 免费版的 **Managed 模式**。组件根据风险自动验证，必要时要求勾选方框，无需识图或输入验证码。同一站点的各码池领码页共用 Widget，无需按码池创建配置。
- Turnstile 只在领取新码时要求验证。查看本地已领取记录、复制兑换码和提交“我已使用”标记不要求重新进行 Turnstile 验证，原有接口校验仍须执行。
- 领取 API 必须在服务端使用 Secret Key 调用 `https://challenges.cloudflare.com/turnstile/v0/siteverify`，检查 `success`、返回的 `hostname` 是否属于配置的站点，以及 `action` 是否为领码操作约定的 `claim`。前端组件同样配置 `action: claim`；不能仅依据前端显示验证成功或请求携带了 Token 就发码。
- 验证 Token 有效期为 300 秒且只能验证一次。缺失、无效、过期、重复使用、站点或操作不匹配时拒绝领取；验证服务超时、异常或配置缺失时也不得跳过验证发码。前端在 Token 过期或领取请求失败后重置组件，重新验证后由用户再次点击领取。响应丢失仍按本期已有规则处理，Turnstile 不提供领取找回或请求幂等能力。
- Site Key 为前端公开配置；Secret Key 通过 Worker Secret 保存，仅供服务端使用，不进入前端构建产物、代码仓库或日志。生产 Widget 配置允许的站点主机名；本地开发和自动化测试使用官方测试密钥，生产环境禁止使用测试密钥。验证 Token 仅在前端内存中暂存，不写入 `localStorage`、业务表或日志。
- 首版防刷只接入 Cloudflare Turnstile，不实现 IP、`IP + 码池` 或其他应用层接口限流，不接入 Workers Rate Limiting；创建空间、登录、领码 Key 校验、领取和使用标记接口均不增加限流逻辑。
- Turnstile 用于提高自动刷码成本，不保证“一人一码”，不能替代数据库中的原子发码；本地记录限领仍只属于浏览器侧规则。

费用说明（2026-09-15 核对）：Turnstile 免费版不限验证次数，每个账户最多 20 个 Widget、每个 Widget 最多 10 个主机名，适用于多数生产应用；企业版需联系销售报价。该免费额度仅指 Turnstile，不代表 Workers、D1 或其他配套服务无费用。

参考：[Widget 与验证模式](https://developers.cloudflare.com/turnstile/concepts/widget/)、[服务端验证](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)、[套餐与限制](https://developers.cloudflare.com/turnstile/plans/)、[官方测试密钥](https://developers.cloudflare.com/turnstile/troubleshooting/testing/)。

## 5. 表结构设计

使用 D1 / SQLite，共四张业务表。ID 使用服务端生成的 UUID（`TEXT`），时间使用 UTC Unix 毫秒时间戳（`INTEGER`），布尔值使用 `INTEGER` 的 `0/1`。除明确标注可空的字段外，其他字段均为 `NOT NULL`。

当前项目的 `counters` 表为保留的演示表，与以下业务表无关联。业务表已在 `src/worker/db/schema.ts` 定义，并由 `drizzle/0001_noisy_veda.sql` 创建。

### 5.1 发码空间 `distributor_spaces`

| 字段         | 类型    | 约束 / 说明                                     |
| ------------ | ------- | ----------------------------------------------- |
| `id`         | TEXT    | 主键                                            |
| `key_hash`   | TEXT    | 唯一，发码 Key 的摘要，用于登录校验，不保存原文 |
| `created_at` | INTEGER | 创建时间                                        |

一个空间对应一个发码 Key，可拥有多个兑换码池和登录会话。

### 5.2 登录会话 `distributor_sessions`

| 字段         | 类型    | 约束 / 说明                                         |
| ------------ | ------- | --------------------------------------------------- |
| `id`         | TEXT    | 主键                                                |
| `space_id`   | TEXT    | 外键，关联 `distributor_spaces.id`                  |
| `token_hash` | TEXT    | 唯一，登录态 Token 的摘要，不保存原文               |
| `created_at` | INTEGER | 创建时间                                            |
| `expires_at` | INTEGER | 固定为创建时间加 7 天（604800000 毫秒），不自动续期 |

索引：`space_id`、`expires_at`。每次创建或登录空间时新增会话，使用同一个 Cookie 名保存当前 Token，成功后替换当前浏览器的登录态；Cookie 持久保存，其到期时间与会话一致，关闭浏览器不会主动清除。退出登录时删除当前会话并清除 Cookie，不影响其他设备会话。服务端仅接受尚未过期且仍存在的会话。

### 5.3 兑换码池 `code_pools`

| 字段         | 类型    | 约束 / 说明                                                   |
| ------------ | ------- | ------------------------------------------------------------- |
| `id`         | TEXT    | 主键                                                          |
| `space_id`   | TEXT    | 外键，关联 `distributor_spaces.id`                            |
| `name`       | TEXT    | 兑换码池名称，去除首尾空白后非空，同一空间内唯一，区分大小写  |
| `claim_key`  | TEXT    | 唯一，领码 Key，用于定位兑换码池                              |
| `status`     | TEXT    | 默认 `active`；仅允许 `active`（发放中）、`stopped`（已停止） |
| `created_at` | INTEGER | 创建时间                                                      |

约束与索引：联合唯一约束 `(space_id, name)`，名称非空检查，索引 `space_id`。领码 Key 保存原文，以支持发码者后续登录后再次复制原 Key 和链接；仅通过所属空间的管理接口提供，不提供公开兑换码池列表。发码 Key 和登录 Token 仍只保存摘要。

停止、恢复仅修改 `status`。追加兑换码不改变兑换码池状态。总数量、已领取数量、剩余数量通过兑换码表统计，不单独存储计数字段。

### 5.4 兑换码 `redemption_codes`

| 字段                  | 类型    | 约束 / 说明                                                                                        |
| --------------------- | ------- | -------------------------------------------------------------------------------------------------- |
| `id`                  | TEXT    | 主键                                                                                               |
| `pool_id`             | TEXT    | 外键，关联 `code_pools.id`                                                                         |
| `code`                | TEXT    | 去除首尾空白后的兑换码原文，长度为 1–100 个 Unicode 码点，区分大小写，用于展示、复制及提交使用标记 |
| `claim_status`        | TEXT    | 默认 `unclaimed`；仅允许 `unclaimed`（未领取）、`claimed`（已领取）                                |
| `claimed_at`          | INTEGER | 可空，领取时间                                                                                     |
| `remark`              | TEXT    | 可空，领码者填写的领取备注，去除首尾空白后最多 500 个 Unicode 码点，未填写时为 `NULL`              |
| `user_marked_used`    | INTEGER | 默认 `0`；仅允许 `0/1`，表示用户是否标记已使用                                                     |
| `user_marked_used_at` | INTEGER | 可空，用户首次标记已使用的时间                                                                     |
| `created_at`          | INTEGER | 导入时间                                                                                           |

约束与索引：

- 联合唯一约束 `(pool_id, code)`：同一码池内的兑换码不重复，不同码池允许相同码内容。
- 联合索引 `(pool_id, claim_status)`：用于选取未领取码及统计库存。
- 状态一致性检查：未领取时 `claimed_at` 为空，已领取时必须有领取时间；未标记使用时 `user_marked_used_at` 为空，已标记时必须有标记时间且兑换码已领取。
- 领取时，先完成参数校验和 Turnstile 服务端验证，再在同一原子操作中重新检查兑换码池为 `active`、选取未领取码并更新领取状态、时间和备注，成功后才返回兑换码；不在数据库原子操作中调用外部验证服务。
- 标记使用时，通过领码 Key 找到兑换码池，再按兑换码更新；兑换码池停止不影响此操作，重复提交仍返回成功，并返回服务端保存的使用标记和首次标记时间，不覆盖首次标记时间。

以上外键均不配置级联删除，首版不提供空间、兑换码池或兑换码的删除功能。
