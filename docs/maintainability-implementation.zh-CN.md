## 事务、配额与统计语义

- 普通导入每 45 行提交一次，保留之前批次可能成功的语义；操作结束检查码池是否仍属于当前空间。500 行整个请求仍为 39 条查询、最多 95 个绑定参数。
- 核销导入每组 60 行构造语句，所有组进入同一个 `DB.batch()`；之前状态结果的位置与语句构造放在一起，取消位置取模。500 行混合状态请求仍为 48 条查询、最多 62 个绑定参数。
- 领取、删除与每次状态转换的明细语句和计数器更新相邻，位于同一批处理；没有新增权限或统计查询。容量、归属与状态写入条件保留。
- `summary.claimed` 和码池的 `claimed` 表示累计成功领取数量，包含后来标记为已兑换的已领取记录；`counts.claimed` 仅表示当前状态为 `claimed` 的记录。核销尚未领取的码不会增加累计领取。
- 导出继续使用读取上界、游标、Web Worker 与批次确认。上界不构成数据库快照，状态以读取时为准；未改动导出批次大小。
- 已重新核对 [D1 限制](https://developers.cloudflare.com/d1/platform/limits/)和[批处理事务语义](https://developers.cloudflare.com/d1/worker-api/d1-database/)。实际计费方案尚未确认，预算继续按免费方案每次调用 50 条查询、每条 100 个绑定参数约束。

业务上限、状态与分页选项归共享 contracts；D1 导入分组大小归业务操作。数据库长度检查仍是持久化约束，修改业务长度上限时必须同时评估新增迁移，不应仅修改 TypeScript 常量。

## 生命周期与会话

`useDialogRequest` 为每次 effect setup 建立独立作用域，使用同步锁阻止同一事件批次重复提交。成功、失败和结束时的 UI 更新均检查作用域是否仍有效。普通弹窗在卸载时取消请求，但取消不表示服务端事务回滚。

认证请求使用不取消传输的作用域：用户离开后不再调用旧 `onDone`，请求结束时通知 App 重读当前 Cookie 对应的会话，不恢复旧导航。成功与失败路径均覆盖导航离开测试。创建成功返回的一次性 Key 交由 App 在内存中暂存，即使原弹窗已卸载也不丢弃；独立保存弹窗逐个等待用户确认，不受会话同步或客户端导航影响。确认保存不会使用创建响应中的旧会话覆盖当前 Cookie 对应的会话，未增加持久化密钥行为。

领取成功的本地记录保存独立于页面 UI 生命周期，保留已有卸载后持久化测试。详情 reducer 统一加载、提交、失败和失效转换，同步状态镜像只通过相同 reducer 更新；列表读取和状态写入继续共用操作锁、取消控制器和生命周期序号。缓存逻辑独立处理键、60 秒过期和 20 项 LRU 淘汰。

## 测试隔离与检查门禁

`tests/api.test.mjs` 是唯一 API 套件入口，导入按业务划分的 `*.cases.mjs`，不为每个业务文件启动一个模拟服务。套件共用一次性 D1 代理，测试串行执行；每项测试完成后先运行独立 SQL 聚合校验，再按外键顺序清理行。故障注入工具用 `finally` 删除触发器。数据工厂显式维护计数器，独立校验不依赖该维护算法。

D1 计量包装完整绑定，覆盖鉴权、归属与业务查询，保留语句参数、扫描量与写入量统计。环境、迁移、计量和故障注入工具已迁到 TypeScript；其余 JavaScript 测试和维护脚本已纳入 ESLint。

通过 GitHub API 检查到当前仓库无 Actions workflow，当前 HEAD 没有 check runs 或 commit statuses，随后增加无生产凭证的 `Check` workflow。该证据不代表仓库外不存在其他部署系统。新增 workflow 尚未推送运行；分支保护和 Cloudflare Builds 等平台的发布门禁需由维护者在实际部署设置中确认。避免重复配置部署任务，workflow 只运行 `npm run check`。

## 运维入口

未知异常日志仅输出固定字段：白名单操作名、错误分类、阶段、随机关联 ID 和耗时。不记录原始路径、SQL 参数、Cookie、Key、兑换码、备注、异常消息或堆栈。`X-Request-ID` 可用于匹配响应和应用日志；客户端提供的同名头不被信任。领取阶段继续复用 `Server-Timing`。

[Workers tracing](https://developers.cloudflare.com/workers/observability/traces/)显式开启，采样率 1%，URL 查询参数脱敏。平台自动 span 的字段和保留策略仍由 Cloudflare 管理；部署后结合真实流量复核。D1 查询始终使用参数绑定，不拼接敏感值到 SQL 文本。

```bash
# 默认一批；清理本地数据库
npm run db:sessions:cleanup -- --local

# 显式选择远程；按需最多十批（本次未执行）
npm run db:sessions:cleanup -- --remote --batches=10
```

每批一条 DELETE，通过 `sessions_expiry_idx` 选择最多 1,000 条 `expires_at <= cutoff` 的会话。一次执行固定截止时间、最多 10 条删除查询和 10,000 条会话删除，不执行全量 COUNT、不返回会话 ID；D1 物理写入数还包括索引维护。遇到不足一批即停止，达到上限报告 `limitReached`。各批独立提交，后续失败不撤销先前批次。没有新增定时器，执行频率待会话增长量与配额数据明确后决定。

计数器全量校验和重建仍为显式维护任务。重建必须暂停所有写入并排空在途请求。
